3. STATE SCHEMA AND REDUCER SEMANTICS
================================================================================

┌────────────────┬──────────┬──────────────────────────────────────────────────┐
│ Field          │ Reducer  │ Semantics                                        │
├────────────────┼──────────┼──────────────────────────────────────────────────┤
│ task           │ LWW      │ Last-write-wins. The current task description.   │
│ plan           │ LWW      │ Last-write-wins. The execution plan.             │
│ status         │ LWW      │ Last-write-wins. Workflow status enum.           │
│ result         │ LWW      │ Last-write-wins. Final output.                  │
│ approvedBy     │ LWW      │ Last-write-wins. Human approver name.           │
│ feedback       │ LWW      │ Last-write-wins. Latest reviewer feedback.      │
│ error          │ LWW      │ Last-write-wins. Error description.             │
│ maxBudget      │ LWW      │ Last-write-wins. Cost ceiling.                  │
│ retryCount     │ Additive │ (a, b) => a + b. Accumulates retry deltas.      │
│ totalCost      │ Additive │ (a, b) => a + b. Accumulates cost from nodes.   │
│ workerResults  │ Append   │ [...a, ...b]. Fan-in from parallel workers.     │
│ messages       │ Append   │ [...a, ...b]. Append-only audit log.            │
└────────────────┴──────────┴──────────────────────────────────────────────────┘

LWW = Last-Write-Wins: (_, newVal) => newVal
Additive = Sum: (current, delta) => current + delta
Append = Concat: (current, update) => [...current, ...update]

4. CHECKPOINT LIFECYCLE
================================================================================

  ┌─────────────────────────────────────────────────────────────────────┐
  │                    CHECKPOINT LIFECYCLE                             │
  ├─────────────────────────────────────────────────────────────────────┤
  │                                                                     │
  │  1. INIT     Thread created → default state saved as checkpoint #0 │
  │                                                                     │
  │  2. NODE     Node executes → partial update returned                │
  │                                                                     │
  │  3. MERGE    Reducers merge partial into full state                 │
  │                                                                     │
  │  4. SAVE     New checkpoint saved (state + next node + metadata)    │
  │                                                                     │
  │  5. NEXT     Follow edge to next node → goto step 2                │
  │                                                                     │
  │  6. INTERRUPT (optional)                                            │
  │     interrupt() called → checkpoint saved with interrupt state      │
  │     → invoke() returns to caller → wait for Command({ resume })    │
  │     → resume: reload checkpoint, interrupt() returns resume value   │
  │     → continue from step 2                                          │
  │                                                                     │
  │  7. END      No next node → final checkpoint saved → return result  │
  │                                                                     │
  │  CRASH:      If process dies between steps 2-3, node re-executes    │
  │              If process dies between steps 4-5, resumes at step 5   │
  │              Completed work is NEVER repeated.                      │
  │                                                                     │
  └─────────────────────────────────────────────────────────────────────┘

7. RETRY CYCLE GUARD MECHANICS
================================================================================

  ┌─────────────────────────────────────────────────────────────────┐
  │                    RETRY CYCLE FLOW                             │
  │                                                                 │
  │  Attempt 1:  worker → reviewer → "revise" → retryCount += 1    │
  │              → costGuard → worker (retry)                       │
  │                                                                 │
  │  Attempt 2:  worker → reviewer → "revise" → retryCount += 1    │
  │              → costGuard → worker (retry)                       │
  │                                                                 │
  │  Attempt 3:  worker → reviewer → "pass" → finalizer → END      │
  │              OR: retryCount >= 3 → finalizer → END (exhausted)  │
  │                                                                 │
  │  Safety nets:                                                    │
  │  • retryCount >= MAX_RETRIES (3) → forced termination           │
  │  • costGuard → totalCost > maxBudget → forced termination       │
  │  • recursionLimit (compile option) → GraphRecursionError        │
  │                                                                 │
  └─────────────────────────────────────────────────────────────────┘

8. CODING CHALLENGE: CRASH RECOVERY SEQUENCE
================================================================================

  Phase 1: Fresh Start
    invoke(input) → planner → humanApproval → INTERRUPT (pauses)
    State saved: { plan: "...", status: "awaiting_approval" }

  Phase 2: Resume with Approval
    invoke(Command({ resume: "approve" })) →
      humanApproval resumes → costGuard → worker →
      ⚡ CRASH (simulated throw in worker on attempt 2) ⚡
    State saved up to last successful checkpoint

  Phase 3: Resume After Crash
    NEW graph instance (same checkpointer, same thread_id)
    invoke(null, config) →
      Loads last checkpoint → resumes at the correct next node →
      reviewer → (retry if needed) → finalizer → END

  Proof:
    ✓ Interrupt paused graph at humanApproval
    ✓ Resume with Command continued execution
    ✓ Crash did not lose completed work
    ✓ New graph instance resumed from correct checkpoint
    ✓ Retry cycle bounded and terminated
    ✓ Final state is "completed"
